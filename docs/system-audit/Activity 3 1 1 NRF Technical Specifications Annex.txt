Purpose of this Annex
This Annex defines the functional, data, security, infrastructure, workflow, testing and documentation requirements for the JOOUST-NRF AI-enabled cultural heritage repository. It is intended to support implementation, procurement, verification and NRF reporting.

1. Purpose and Scope
The repository shall provide a secure, scalable and culturally responsive platform for ingesting, storing, processing, retrieving and presenting Luo Indigenous Knowledge Systems content collected in Homa Bay, Kisumu and Siaya.
SCP-01  Provide controlled storage of raw and curated datasets.
SCP-02  Enforce consent- and sensitivity-based access controls.
SCP-03  Support AI-assisted search, classification, linking and storytelling.
SCP-04  Provide research-grade exports for NLP and computer-vision pipelines.
SCP-05  Support long-term preservation and auditable governance suitable for NRF reporting.

2.2 Access Control
The repository shall implement Role-Based Access Control (RBAC) together with Attribute-Based Access Control (ABAC).
IAM-01  Apply restriction_level values: public, internal, restricted and sacred.
IAM-02  Apply consent_scope values: research_only, teaching, public_excerpt, community_only and embargoed.
IAM-03  Apply county and site filters where community rules require locality-based governance.
IAM-04  Apply object-level rules separately to each cultural record, media asset and transcript.
2.3 Authentication
IAM-05  Use JOOUST single sign-on where available; otherwise use an OIDC provider, with Keycloak recommended.
IAM-06  Require multi-factor authentication for administrator and curator accounts.
IAM-07  Enforce session timeouts and device-login controls for elevated roles.
3. Functional Specifications
3.1 Content Ingestion and Registration
FUN-01  Provide batch ingestion by folder upload and single-item upload.
FUN-02  Require metadata at ingest: domain, genre, county/site, consent and restriction.
FUN-03  Perform automated file-integrity checks and store SHA-256 checksums.
FUN-04  Extract technical media metadata, including duration, format and resolution.
FUN-05  Support the status workflow: raw -> transcribed -> reviewed -> validated -> curated -> published.
3.2 Data Storage and Retrieval
FUN-06  Store multimodal files in an on-premises object store using local NAS or S3-compatible storage.
FUN-07  Store metadata, consent, access rules and indices in a relational database.
FUN-08  Provide keyword search and filters for domain, genre, county, site and restriction.
FUN-09  Provide AI-based semantic search through vector similarity for authorized users.
3.3 AI-Enabled Discovery
AI-01  Classify genres including proverb, riddle, folk story, song and ritual narrative.
AI-02  Apply theme tags aligned to elicitation domains, including governance, kinship and ecology.
AI-03  Extract named entities such as sites, artifacts, clans and practices, subject to curator validation.
AI-04  Cross-link records to artifacts, sites and practices through a knowledge-graph layer.
AI-05  Provide a storytelling presentation module for permitted, non-sacred narratives, including linked audio excerpts and glossary content.
3.4 Community Validation and Feedback
FUN-10  Provide a private validation workspace for custodians to review curated items.
FUN-11  Capture approve, revise and restrict feedback decisions with an audit trail.
FUN-12  Permit curator-controlled revision of restriction levels following community decisions.
3.5 Export and Interoperability
INT-01  Export authorized NLP training content in JSONL format.
INT-02  Export authorized computer-vision datasets in COCO/CSV style, including images, labels and metadata.
INT-03  Export metadata in CSV and JSON formats.
INT-04  Provide internal API endpoints for analysis scripts and the web portal.
4. Data Model Requirements
4.1 Core Objects
Object
Required content and relationships
Cultural Record
Central unit containing domain, genre, summary, county/site, restriction and consent linkage.
Media Asset
Audio, video or image; URI; checksum; technical fields; and restriction override.
Transcript / Translation / Annotation
Versioned object linked to media assets and cultural records.
Artifact Record
Artifact type, use, materials, media and links to narratives and practices.
Entities and Relationships
Knowledge-graph relationships among artifacts, practices, sites and narratives.

4.2 Versioning and Provenance
Every transcript and curated object shall support version numbering and provenance logs recording:
the person who created or edited the object;
the date and time of the action;
the content that changed; and
the source media or segment used.
5. Non-Functional Specifications
5.1 Performance and Capacity
Requirement
Minimum target
Metadata search response
No more than 2 seconds under typical loads.
AI semantic-search response
No more than 5 seconds, subject to index size.
Concurrent users
Baseline of 20 internal users, scalable to 100 or more.
Media storage growth
Support 2-10 TB over the project lifecycle.
Transcript-segment growth
Support 50,000-500,000 transcript segments.

5.2 Availability and Resilience
NFR-01  Achieve at least 99% availability during working hours.
NFR-02  Perform daily incremental backups and weekly full backups to JOOUST-controlled on-premises storage.
NFR-03  Maintain an on-premises disaster-recovery plan capable of restoring the metadata database and object store within 48-72 hours.
NFR-04  Keep backup copies on physically or logically separate JOOUST-controlled on-premises infrastructure; no operational or backup data shall depend on public-cloud services.
5.3 Security
SEC-01  Encrypt server volumes at rest; use object-store encryption where supported.
SEC-02  Use TLS/HTTPS for all web traffic.
SEC-03  Apply least privilege across users and services.
SEC-04  Audit authentication events, content views/downloads, restriction changes and export events.
5.4 Privacy and Ethical Safeguards
ETH-01  Support pseudonymization of participant identifiers.
ETH-02  Place consent forms in a separate secure enclave and restrict direct access.
ETH-03  Generalize location data, where required by consent and sensitivity, to site level rather than exact GPS coordinates.

6.2 Deployment Footprint

ARC-02  Host application, database, search, vector retrieval, object storage and AI-inference services within JOOUST-controlled infrastructure.
ARC-03  Use only JOOUST-controlled on-premises backup and replication targets; cloud mirroring and cloud-hosted operational services are out of scope.
7. Repository Workflows
7.1 Ingest Workflow States
State
Definition
Raw ingested
Media stored; metadata minimal; restricted by default.
Transcribed
AI-generated draft transcript exists.
Reviewed
Transcript has undergone manual verification and cleaning.
Validated
Approved by a linguist or cultural-heritage reviewer.
Curated
Metadata enriched; glossary, annotations and links created.
Published
Exposed only according to access-control rules.

7.2 Publication Rules
Nothing shall become public unless all of the following conditions are satisfied:
consent_scope permits public access;
restriction_level is public; and
curator approval has been granted.
8. File and Naming Conventions
The repository shall adopt deterministic file URIs.
/JOOUST/NRF/LuoAI_Repository/02_fieldwork/{county}/{site}/{session_id}/domain={domain_code}/raw/{media_type}/{asset_id}.{ext}
Processed derivatives shall follow:
.../processed/transcripts/{version}/{asset_id}_transcript_v{n}.txt
Every asset shall have a unique asset_id and a stored checksum.

9. Testing and Acceptance Criteria
Acceptance shall be based on witnessed functional tests, configuration inspection and retained evidence. A criterion passes only where the expected result is achieved without exposing content beyond its authorized scope.
